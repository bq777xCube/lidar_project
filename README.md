# Обнаружение препятствий для беспилотного метро

**Поток 3D-лидара → признак препятствия → расстояние и состояние в ROS 2.**

CPU-решение команды **Neapy** для задачи № 5 хакатона «Лидеры цифровой трансформации 2026». Исходный код, Dockerfile, параметры и сценарии воспроизведения находятся в этом репозитории. Для работы не требуются GPU, обученные веса или подключение алгоритма к внешнему сервису.

**[Документация](docs/README.md)** · **[Запуск](docs/DEPLOYMENT.md)** · **[Результаты](docs/RESULTS.md)** · **[Проверка](docs/VALIDATION.md)**

## Что делает решение

По текущему облаку определяется рельсовая геометрия и проверяется габарит движения. Разреженные наблюдения дополнительно подтверждаются во времени. Для предоставленных синтетических вставок работает отдельный признак несогласованности с лучевой структурой лидара, включая поддержку при приближении объекта.

## Проверенные результаты

| Проверка | Итог |
|---|---|
| Выбранные синтетические примеры | Обнаружения на 98,7 / 99,1 / 99,4 / 72,6 м |
| Локальный поток 10 Гц | 500 из 500 входов завершены в каждом из четырёх прогонов |
| Задержка публикация → завершение обработки | p95 68,2–74,3 мс; Linux ARM64 VM на Apple M4 |
| Упаковка | ROS 2 Humble, Docker, поддержка предоставленных форматов 16/26 байт на точку |

Дальность около 100 м относится к прямо проверенным **синтетическим примерам**. Основной канал использует измеренную геометрию пути; синтетический признак не является универсальным детектором физических объектов. Полные результаты, известные ошибки и условия измерений: **[Результаты проверки](docs/RESULTS.md)**.

## Быстрый запуск на предоставленной записи

Из корня репозитория, на машине с установленным Docker:

```bash
docker build --platform linux/amd64 -t lidar-near:v5-query-first-ru .
bash scripts/demo_synthetic.sh /absolute/path/to/cloud_with_fake_obj
```

Для реальной записи с топиком `/lidar_points`:

```bash
bash scripts/demo_real.sh /absolute/path/to/real_bag
```

Сценарий запускает узел, плеер и наблюдатель в **одном контейнере**, проверяет входной топик и готовность подписчиков. Bag монтируется только для чтения. Результаты сохраняются в `demo_results/`.

По умолчанию это короткое воспроизведение с коэффициентом 0.1 для синтетики и 0.2 для реальной записи. Скорость, интервал исходного времени и смещение передаются явно:

```bash
bash scripts/demo_synthetic.sh /absolute/path/to/cloud_with_fake_obj 0.1 2.4 76.95
```

**[Полная инструкция](docs/DEPLOYMENT.md)** включает интерактивный запуск, внешнего ROS-публикатора, смену топика и резервную конфигурацию. Сборка требует доступных базового образа и пакетов либо их кэша; готовый узел работает автономно. Исходные bag и экспорт Docker-образа не вложены в репозиторий.

Краткий [маршрут проверки](docs/REVIEW_ROUTE.md) объединяет результаты, запуск и контракт.

## Что проверить в первую очередь

```bash
# Структура, контрольные суммы, ссылки и синтаксис. Достаточно Python 3.
python3 validation/check_repository.py

# Локальные проверки интерфейса и ядра. Нужен NumPy.
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
```

Для выполнения локальных проверок в собранном образе:

```bash
docker run --rm --platform linux/amd64 --network none \
  -e NEAPY_USE_INSTALLED=1 -e PYTHONDONTWRITEBYTECODE=1 \
  -v "$PWD/tests:/checks/tests:ro" \
  lidar-near:v5-query-first-ru \
  python3 -m unittest discover -s /checks/tests -v
```

Локальные тесты проверяют контракт входа, конфигурацию и базовую работу ядра. Полная проверка на эталонных облаках описана отдельно в **[инструкции валидации](docs/VALIDATION.md)**; большой проверочный комплект передаётся отдельно и не входит в Docker-контекст.
