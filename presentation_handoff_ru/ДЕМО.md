# Запуск и интеграция

Это инструкция к уже поставленному решению. В архиве для автора презентации нет runtime, bag-файлов и проверочных кэшей. Оформление материалов не требует запуска детектора.

Полные исходные инструкции сохранены в [technical/docs/DEPLOYMENT_RU.md](technical/docs/DEPLOYMENT_RU.md) и [technical/docs/API_RU.md](technical/docs/API_RU.md). Команды ниже используются только при отдельно запланированной демонстрации.

Из каталога распакованных архивов поставки:

```bash
gzip -dc lidar-near-v5-query-first-ru-amd64.tar.gz | docker load
cd solution
bash scripts/demo_synthetic.sh /absolute/path/to/synthetic_bag
# Для реальной контрольной записи:
bash scripts/demo_real.sh /absolute/path/to/real_bag
```

Имя каталога solution зависит от выбранного при распаковке пути. Bag монтируется только для чтения. Сценарии проверяют topic и готовность узла. Существующее видео в media/ показывает фактическое воспроизведение записи при 0,1x/0,2x под эмуляцией AMD64 на M4. Это не нагрузочный тест 10 Гц и не проверка i7.

Вход: /lidar_points, sensor_msgs/msg/PointCloud2. Основные результаты: /foreign_object/obstacle и /foreign_object/distance. Также публикуются state, horizon, processing_ms, track_quality и source в пространстве /foreign_object/.

Семь отдельных сообщений не имеют общей временной метки. Потребитель должен контролировать свежесть и не соединять старое расстояние с новым состоянием как гарантированно единую пару. Отсутствие свежих данных означает неопределённость. Остановка входа не публикует автоматическое «путь свободен». Контроль свежести описан в API.

Приложенный MP4 и его подтверждение происхождения сохранены. Перед показом выберите нужный фрагмент и не называйте его проверкой на оборудовании заказчика. Перезапуски в рамках данной редакции не выполнялись.
